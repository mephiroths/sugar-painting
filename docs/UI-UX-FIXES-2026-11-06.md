# 糖画铺：发布前 UI / UX 修改记录

已按本轮审查实施修改，保留现有招牌、木桌、纸签、朱红和三维糖画风格。更新后的独立文件是项目根目录的 `糖画铺.html`；网页发布包在 `artifacts/vercel-site/`。本轮没有部署或发布。

## 审查项对应结果

| 审查项 | 修改后的行为 | 验证依据 |
|---|---|---|
| 01 小屏核心操作出屏 | 移除 740px 最小高度，核心操作留在可视区域；横屏使用侧边工具布局 | 专项测试的 320×568、390×844、568×320、844×390、1028×884、1440×900 检查 |
| 02 印记太淡、没有起点 | 增强印记深浅与线宽，默认逐笔引导和起笔圆圈；绘画默认斜视，观看保留斜视 | DOM 状态、实际截图、起笔和落糖检查 |
| 03 第一笔即宣告作品完成 | 首笔后优先“继续描画”，保留“先拿起来看看”；欣赏页改为“先看看这份甜”，允许返回修改 | 专项测试的落笔、继续、预览、撤销与重做 |
| 04 保存动作容易混淆 | 改为“保存并去糖画架”和“保存并画下一幅”；共用命名表单，明确清空行为、目的地，取消不清空；默认名称避开已有同名作品 | 实际具名入架、专项测试的失败重试与保存后清空 |
| 05 提示与按钮名不一致 | 四语提示对应“拿起来看看 / Lift and admire”；关闭印记或逐笔引导后更新提示，不再要求寻找不存在的圆圈 | 四语切换及源码检查 |
| 06 小字与小点击区域 | 语言、移动画布、图案入口、关闭练习与核心工具高度不低于 44px；功能文字采用清晰正文体系 | 四语小屏尺寸断言及截图 |
| 07 图案双重滚动、词被拆开 | 手机图案库使用两列、自然词换行、单一面板滚动和明确关闭按钮；Escape 返回触发器 | 四语两列、名称宽度与焦点回归检查 |
| 08 绘画空间与界面争抢 | 为绘画画布预留独立区域，按比例取景；从预览返回、改变尺寸和模板链接直接进入时保持绘画斜视 | 六种视口下画板边界投影均在画布内 |
| 09 详情六个动作等权 | 分享和回看保留在详情，修改、图片、视频、删除收进“更多操作”；整理实际 DOM 顺序，保持键盘与视觉顺序一致 | 实际详情菜单和专项测试 |
| 10 字体与装饰层级 | 品牌和主动作保留书写感；说明、语言、设置、图案名称改用正文；创作中收起侧边纸签 | 手机与桌面截图 |
| 11 重复图案入口 | 删除第三个“选图案”入口；侧签仅作为观看模式快捷图案，绘画时使用完整图案库入口 | DOM 与实际页面检查 |
| 12 海报主体不突出 | 使用独立相机按糖画和竹签边界取景，背景换为干净暖色；用离屏目标生成图像，不改变主画布大小 | 完整蝴蝶海报截图，1200×1500 尺寸和关闭分享后画布/焦点恢复断言 |

另修正了在示范仍播放时点击“欣赏示范成品”的行为：先重建完整示范，再展示成品。

## 绘画默认视角修正

“照着画”和“自由画”统一使用约 34° 的自然斜视。直接打开、刷新、进入练习、切换模式、从成品返回修改，均使用同一默认视角；“俯着看”继续作为手动选项。相机按石板四角与实际画布比例计算距离，兼顾手机、横屏和桌面完整取景。专项检查同时验证相机实际位置与目标方向，避免仅更改模式名称却仍使用垂直视角。

## 第二轮补充修复

- 视频导出在回放期间移到独立可见面板，生成、取消和下载入口不会随“更多操作”关闭而隐藏；生成完成时将下载入口滚动到可见位置。
- 手机回放的播放栏与“返回工作台”分开布局；紧凑横屏可在导出面板内滚动，保留外部播放和返回入口。
- 作品详情的“更多操作”新增“返回工作台”，回到当前草稿；“继续修改”仍用于打开选中的存档作品，两个动作含义明确。
- 回归脚本通过正常菜单入口操作；检查原画保留时先等待糖层冷却稳定，避免将自然冷却误判为回放修改了作品。

## 尚未由本轮证明的范围

手机截图是尺寸模拟，仍需实体设备验证触摸手感、系统分享、微信内置浏览器、发热和性能。没有执行实际对外分享或公开部署验收，也没有进行完整读屏合规认证或陌生用户可用性测试。视频已验证生成、下载及可解码；全部音轨、竖屏画幅和真机视频仍需单独验收。

上述检查在已有 Chromium 上通过；没有执行整个 `npm run verify` 历史测试集，不能视作所有测试、浏览器和设备都已通过。

这轮修改解决已确认的交互和布局问题；“世界级”体验仍需真实用户试用与真机数据继续检验。
