# 糖画铺发布前 UI / UX 审查

审查日期：2026-11-06。对象：当前工作区的糖画铺开发预览 `http://127.0.0.1:5177/`。本报告检查当前运行版本，未修改产品代码；工作区已有未提交修改，不能将此报告视为已发布版本的验收。

## 判断

作品有清楚的文化辨识度：木桌、纸签、朱红主动作、铜勺与石板共同构成了完整场景；从观看切到亲手创作的入口也很明确。但当前体验尚未达到适合大范围推广的精细程度。优先修复描画可见性、小屏工具可达性、保存动作语义和首次成功体验，再打磨装饰、字体和分享构图。

“世界级”在本项目中应以这些结果检验：陌生用户无需解释就能开始；在第一次练习中做出自己愿意留下的图案；操作和提示完全对应；手机上随时能撤销和完成；保存后知道作品在哪里、是否清空了画板；收到分享的人看得清作品并理解它是什么。以下是专家审查，尚非真实用户验证。

## 实测范围和证据边界

- 实际体验：观看 → 我也来画 → 画一笔 → 欣赏 → 保存入架 → 详情 → 生成分享海报；另查图案选择、调节、语言切换和键盘 Escape 返回。
- 视口：默认约 1028×884、1440×900、390×844、320×568。手机尺寸为桌面浏览器模拟，未验证实体手机触感、浏览器地址栏变化、发热或弱网性能。
- 当前运行截图存于 `../artifacts/audit-2026-11-06/`；均为本轮捕获并重新读取检查的文件。分享加载中的截图已被完成状态替换。
- 本轮保存了一份测试短笔画，系统自动命名为“福禄葫芦”。已有作品未删除。不能把截图中的短线造型当作系统绘制完整葫芦失败；本轮主动只画了一笔。
- 未测试实际系统分享发送、公开网站链接、视频成片、备份导入导出、存储失败恢复、屏幕阅读器完整流程、降低动态效果、真机多浏览器和性能。本轮未发送海报、部署或发布作品。
- 对低对比的判断来自画面观察，未对三维纹理背景计算可靠的对比度数值，也不构成无障碍合规认证。

## 已确认的优点

- 品牌、工具、材料之间的视觉关系清楚，值得沿用；不需要另起一套通用网站外观。
- “我也来画”主入口明显，直接进入入门葫芦；无需登录即可尝试。
- 真正走通了绘制、拿起、入架、再打开、生成海报的链路。
- 分享面板有加载、就绪与本地链接限制说明，生成后提供预览；没有把本地地址伪装成公开作品链接。
- 图案按钮有可访问名称和选中状态；本次键盘 Escape 能关闭图案面板并把焦点返回触发器，可见焦点框存在。
- 这些局部检查不能代表整个产品已经通过键盘或屏幕阅读器验收。

## 建议实施顺序

1. 先修 01、02、05：保证手机核心操作无需滚动，增强模板/起笔引导，统一文案。它们最直接影响第一幅能否画下去。
2. 再修 03、04：清楚区分练习、预览与完成，统一保存语义、目的地与命名。用一幅真实完成的作品重走端到端流程。
3. 再做 06—10：收敛工具与字级，按观看、绘画、欣赏分别取景，完善小屏双语布局。
4. 最后打磨 11、12：简化入口，用完整作品优化分享构图。

## 发布门槛建议

以下是建议的验收目标，尚未测得这些结果：

- 找 5 位未用过作品的人，至少 4 位无需口头帮助即可进入绘画、画出第一笔并找到撤销。
- 同一组用户至少 4 位能正确预测两个保存动作分别去哪里、会不会清空画板；操作后能找回作品并继续修改。
- 用 320×568、390×844、横屏和放大文字检查：当前笔画、撤销和完成始终能到达，重要操作不依赖悬停。
- 真机检查 iOS Safari、Android Chrome、微信内置浏览器的长按、拖动、系统分享、后台恢复与性能；不能用本轮桌面尺寸模拟替代。
- 用纯键盘走完观看、模板选择、设置、保存和分享面板；读屏检查名称、状态播报、焦点返回及三维区域的替代说明。
- 公开 HTTPS 环境验收首次加载、海报下载、实际分享取消/失败恢复、链接目的地和预览图；再验证单文件离线版与网页版的一致性。
